# 项目文档

本目录将规划、执行、当前状态和验证证据分开维护，确保每份文档只承担一种权威职责。

## 文档地图

| 文档                              | 职责                                   | 更新时机           |
| --------------------------------- | -------------------------------------- | ------------------ |
| [`ROADMAP.md`](ROADMAP.md)        | 阶段顺序、依赖关系和优先级             | 范围或顺序变化时   |
| [`STATE.md`](STATE.md)            | 当前已验证状态、活跃阶段、阻塞和下一步 | 每次阶段切换时     |
| [`RUNBOOK.md`](RUNBOOK.md)        | 稳定的阶段流程和门禁规则               | 仅在流程本身变化时 |
| [`specs/`](specs/README.md)       | 权威产品与技术决策：为什么做、要做什么 | 制定实施计划前     |
| [`plans/`](plans/README.md)       | 可执行阶段计划：如何做、按什么顺序做   | 每个阶段一份计划   |
| [`evidence/`](evidence/README.md) | 验证输出和可复现证据                   | 阶段收尾过程中     |

## 核心规则

每类事实只能有一个权威归属：

- 产品行为和验收标准写入规格。
- 阶段顺序和依赖关系写入路线图。
- 当前事实写入状态快照。
- 可重复执行的流程写入运行手册。
- 实现细节写入阶段计划。
- 测试结果和截图写入验证证据。

不要在多份文档中复制同一份检查清单，应链接到唯一权威来源。

## 阶段生命周期

```text
草拟 → 就绪 → 进行中 → 已验证
                │          │
                ↓          ↓
              已阻塞      已延后
```

只有满足入口门后，阶段才能进入“就绪”；只有所有退出条件都有最新证据时，阶段才能进入“已验证”。

## 规划入口

正式规划项目时：

1. 创建或确认权威规格。
2. 填写 `ROADMAP.md` 中的阶段表。
3. 使用 `plans/PHASE_TEMPLATE.md` 创建第一阶段计划。
4. 在 `STATE.md` 中设置活跃阶段和下一步。
5. 按照 `RUNBOOK.md` 执行。
